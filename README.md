# Expo-Lead-Agent 🚀

> **海外展会线索智能录入与全自动 AI 商业背调系统**
>
> 专为出海商务与跨国销售团队打造。将展会现场“碎片化、低门槛的随意录入”与后台“高确定性清洗、严谨全网去噪背调、数字化资产自动回写”深度结合，构建从一张名片到一份深度研报的秒级全自动全链路闭环。

---

## 🌟 核心解决痛点

在海外展会（如 Hannover Messe, Automatica 等）现场，一线销售往往手忙脚乱，收集到的线索高度碎片化（拍照模糊、信息残缺、仅有口头备注、存在大量小语种或现场手写修改）。传统的传统 OCR 录入系统或手工登记存在以下致命问题：
1. **录入成本高/数据错配**：国际公司前后缀多（Inc., GmbH, Ltd.），极易造成 CRM 重复建档或查重失效。
2. **背调耗时且存在信息黑洞**：销售跟进前需花费大量时间人眼检索对方背景，对于缺乏公开数字足迹的私有小公司容易遭遇幻觉欺诈或错失黄金切入点。
3. **数字化资产断层**：调研报告大多散落在本地文档，无法与企业 CRM 动态关联。

**`Expo-Lead-Agent` 基于 Coze 高级开发 SDK 与 飞书多维表格（Bitable）生态构建，全自动流转两条核心业务流水线，实现数据录入即背调、资产无缝沉淀。**

## ✨ 核心功能矩阵

### 功能一：多模态智能名片建档与防呆查重
* **多模态名片深度解析**：利用旗舰级多模态大模型，支持现场反光、折角、模糊名片的视觉识别。完美支持多语言/小语种翻译、手写修改自动覆盖（如手写电话优先于印刷电话）。
* **碎片化文本语义槽填充**：自动理解销售现场录入的随意文本，提取出 `意向产品`、`预计需求量`、`价值标签`、`下一步行动` 等衍生高价值线索。
* **联合主键三维去重策略**：采用【清洗后的域名/官网】+【邮箱后缀】+【公司名称 Levenshtein 字符串相似度（≥50%）】的三维联合查重。发现潜在重复时，自动触发“增量合并机制”，以时间戳形式将新线索追加到现有备注，绝不暴力覆盖历史交互数据。
* **环境降级防崩溃**：当图片因网络问题下载失败或 404 时，系统自动优雅降级为纯文本语义解析，确保前线业务绝不中断。

### 功能二：全自动去噪全网背调与 CRM 自动沉淀
* **全自动多阶段流水线**：销售只需在飞书群中丢入名片，系统在建档成功后无需人工干预，自适应提取公司主键，全自动激活后台在线背调流水线。
* **5大维度全景研报生成**：自动从官网、社交媒体等渠道深度网罗并输出标准 Markdown 商业报告：
  * **基本面与赛道定位**（主营业务、商业模式、竞争对手）
  * **规模与健康度**（官方工商实体状态、是否包含经营异常/法律诉讼、上市公司财报状况）
  * **组织架构**（关键决策人、采购/技术切入点）
  * **动态与新闻**（近3-6个月重大动态、招聘动向）
  * **口碑案例**
* **风控置信度标注**：当全网信息源严重不足时，报告顶部会加粗高亮标注 `[置信度：低]` 并发出销售风险提示，严格压制大模型幻觉，做到每条结论均可严谨引注。

## 🛠️ 工程高光亮点（Engineering Excellence）

本系统在实际迭代中，重点解决了多模型组合、第三方平台 API 约束等多个工业级落地踩坑点，实现了极高的数据鲁棒性：

1. **超链接对象合规格式化写入（解决超链接转换异常）**
   飞书多维表格对「超链接（Link）」字段的类型校验极度严格。系统重构了字段清洗层（`_sanitize_crm_fields`），自动将大模型生成的裸字符串网址重新包裹为飞书原生标准的 `{"link": "url", "text": "查看背调报告"}` 结构体对象，实现多维表格侧的蓝色高亮美观跳转，避免了接口拒绝（URLFieldConvFail）。
2. **双层漏斗式数据瘦身机制（解决 Token 爆炸与超时崩溃）**
   针对联网搜索带回的大量无关噪音数据（如公司重名带来的行业噪声），系统在工具层设计了**双层裁剪漏斗**：先对单条搜索内容的 `content` 强制截断至 1500 字符，再对总返回数据在 JSON 序列化后强制控制在 12000 字符以内。这一举措成功**压减了 80% 的冗余 Token 消耗**，将单次 AI 深度背调的响应耗时从几分钟直接缩短至 **16 秒左右的黄金秒级响应时代**，彻底杜绝了网关超时。
3. **面向大模型 Schema 的参数隔离设计（解决模型幻觉污染）**
   在工具函数签名中彻底剥夺了大模型对底层表格资产 ID（`app_token` / `table_id`）的控制和决定权。通过底层的动态参数隔离，100% 锁死强制从系统开发环境变量中读取真实数据库配置，彻底根治了大模型照猫画虎模仿提示词样例、导致向测试假 ID 发送请求的顽疾（NOTEXIST）。

## 🚀 快速开始与部署指南

由于项目高度接入了 Coze 的云端凭证身份中心（`coze_workload_identity`），您**不需要**在代码里硬编码任何敏感的企业 Secret 密钥，只需通过扣子平台的托管网关一键打通。

### 1. 飞书多维表格（CRM）配置

在您的飞书多维表格中，新建一张数据表，并**严格**确保包含以下表头名称（类型需对齐）：

* `公司名称` (单行文本)
* `官网` (URL/单行文本)
* `邮箱` (单行文本)
* `数据状态` (单选，选项配置为：`待跟进`, `调研中`, `调研完成`)
* `跟进记录/展会备注` (💡 多行文本，用于 Agent 追加展会碎片备注)
* `AI调研报告链接` (🔗 超链接字段，用于 Agent 自动回写 PDF 报告)

### 2. 注入配置变量

前往 **Coze (扣子) 平台高级代码模式/IDE 后台**，在 **"Environment Variables"** 面板中以键值对形式注入您的多维表格地址标识（可在表格的浏览器 URL 中提炼）：

* `FEISHU_CRM_APP_TOKEN` = `您的飞书多维表格 app_token` (通常以 bas 开头)
* `FEISHU_CRM_TABLE_ID` = `您的子数据表 table_id` (通常以 tbl 开头)

### 3. 发布与 Webhook 接通

1. 在 Coze 平台点击右上角 **Publish (发布)**。
2. 勾选 **飞书（Lark/Feishu）渠道**，跟随弹窗的傻瓜式图文指引完成飞书自建机器人的授权绑定。
3. 扣子会自动为您托管并生成专属的 Webhook 监听 URL，只需将其复制粘贴至飞书开放平台的“事件订阅”中，并开启消息接收事件（`im.message.receive_v1`）。
4. 将机器人拉入您的展会前线销售群，即可开始享受全自动录入。
